# Совместная разработка

Репозиторий приватный. Доступ получают участники, которых приглашает владелец. Условия распространения исходников остаются UNLICENSED до отдельного решения владельца.

## Первый запуск

Установите Git и Node.js 24 LTS. Клонируйте репозиторий, выполните `npm ci`, затем `npm start`. Для браузерной версии используйте `npm run dev`. Проверки запускаются командой `npm test`; Windows-сборка создаётся командой `npm run build`.

## Ветки

- `main` — стабильное состояние для выпуска.
- `develop` — интеграция проверенных изменений для следующей версии.
- `feature/<краткое-название>` — отдельная новая возможность.
- `fix/<краткое-название>` — исправление ошибки.
- `docs/<краткое-название>` — документация.
- `release/<версия>` — подготовка выпуска, если для него требуется отдельная ветка.

Каждую новую задачу начинайте отдельной веткой от актуальной `develop`:

```sh
git switch develop
git pull --ff-only origin develop
git switch -c feature/spell-combinations
```

Делайте небольшие коммиты и отправляйте ветку:

```sh
npm test
git add <изменённые-файлы>
git commit -m "feat: add spell combinations"
git push -u origin feature/spell-combinations
```

Откройте pull request с целевой веткой `develop`. Опишите проблему, результат и проверки; для графики приложите скриншот. Попросите другого участника просмотреть изменения. После проверки объедините PR и удалите завершённую рабочую ветку. Для выпуска создавайте PR из `develop` в `main` и ставьте тег версии после проверки сборки.

Это соглашение команды. Оно не утверждает, что GitHub технически запрещает прямой push: ограничения веток зависят от отдельно настроенных правил и возможностей аккаунта.

## Что проверять

- Для изменения игровой логики добавьте целевой тест в `tests/`, если он проверяет реальное поведение.
- Для интерфейса проверьте игру при 1280×720, клавиатуру, мышь, паузу и восстановление сохранения.
- Для изменения формата сохранений предусмотрите совместимость или явную миграцию версии.
- Не добавляйте в Git `node_modules`, готовые сборки, ZIP, профили Chromium, сохранения, ключи и `.env`.
- Дистрибутивы передавайте через Releases или артефакты сборки, а не коммитами в исходники.

Карта проекта и игровые правила находятся в README. Перед релизом используйте `docs/QA.md` и `docs/RELEASE.md`.
